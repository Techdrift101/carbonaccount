# Carbon Account API

A training project: a REST API for a sustainable-banking "carbon account". A business holds an account (sort code, account number, balance) that also tracks how far it has cut its carbon emissions. The closer the business gets to net zero, the lower the interest rate on its lending.

Built with Node.js, Express and Amazon DynamoDB, based on an earlier `account` API exercise.

## Running it

```bash
npm install
npm run dev        # starts the API with nodemon on port 3000
```

Or with Docker Compose, which also starts a local DynamoDB on port 8000:

```bash
docker compose up
```

Environment variables (in a `.env` file, which is git-ignored):

| Variable | Purpose |
| --- | --- |
| `DYNAMODB_REGION` | AWS region, e.g. `us-east-1` |
| `DYNAMODB_ENDPOINT` | Set to the local DynamoDB URL when testing locally; leave unset for real AWS |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | AWS credentials (any values work for DynamoDB local) |
| `NODE_ENV`, `PORT` | Used by the Docker build |

The DynamoDB table is defined in `carbonaccount_database.tf` (Terraform).

## Endpoints

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/carbonaccount` | List all accounts |
| `POST` | `/carbonaccount` | Create an account |
| `GET` | `/carbonaccount/:id` | Get one account |
| `PUT` | `/carbonaccount/:id` | Update an account (send the full record) |
| `DELETE` | `/carbonaccount/:id` | Delete an account |

## Account fields

| Field | Type | Sent by client? | Notes |
| --- | --- | --- | --- |
| `id` | string | No | Generated by the API (UUID) |
| `sort_code` | string | Yes, required | |
| `account_number` | number | Yes, required | |
| `balance` | number | Yes, required | |
| `baseline_emissions` | number | Yes, optional | **New.** Annual emissions when the account was opened, in tonnes CO2e. Defaults to `0` |
| `net_carbon_reduction` | number | Yes, optional | **New.** Total reduction achieved against the baseline, in tonnes CO2e. Defaults to `0` |
| `net_zero_progress` | number | No | **New, calculated.** Percentage of the way to net zero, 0–100 |
| `interest_rate` | number | No | **New, calculated.** Interest rate in percent |

If a client sends `net_zero_progress` or `interest_rate`, the API ignores them and works them out itself.

### Example request

```http
POST /carbonaccount
Content-Type: application/json

{
  "sort_code": "12-34-56",
  "account_number": 12345678,
  "balance": 1000,
  "baseline_emissions": 200,
  "net_carbon_reduction": 50
}
```

### Example response

```json
{
  "message": "Successfully created account",
  "data": {
    "id": "6f1c2a0e-...",
    "sort_code": "12-34-56",
    "account_number": 12345678,
    "balance": 1000,
    "baseline_emissions": 200,
    "net_carbon_reduction": 50,
    "net_zero_progress": 25,
    "interest_rate": 6.5
  }
}
```

## How the interest rate is calculated

```
net_zero_progress = net_carbon_reduction / baseline_emissions   (capped at 100%)
interest_rate     = 8% − (8% − 2%) × net_zero_progress
```

The rate falls in a straight line from a base rate of **8%** (no reduction) to a minimum of **2%** (net zero reached). Both values are rounded to two decimal places.

| Baseline | Reduction | Progress | Interest rate |
| --- | --- | --- | --- |
| 200 | 0 | 0% | 8% |
| 200 | 50 | 25% | 6.5% |
| 200 | 100 | 50% | 5% |
| 100 | 100 | 100% | 2% |
| 100 | 150 | 100% (capped) | 2% |
| 0 | any | 0% | 8% |

If no baseline is set, progress can't be measured, so the account pays the base rate.

To change the rates, edit `BASE_INTEREST_RATE` and `MIN_INTEREST_RATE` at the top of `models/carbonaccount.js`.

## What changed in this update

### `models/carbonaccount.js`

- Added `baseline_emissions` and `net_carbon_reduction` to the Joi validation schema. Both must be zero or more and default to `0`.
- Added `net_zero_progress` and `interest_rate` to the schema as fields that are stripped from client input.
- Added `BASE_INTEREST_RATE` and `MIN_INTEREST_RATE` constants.
- Added a `withCarbonFields()` helper that fills in defaults and calculates `net_zero_progress` and `interest_rate`.

### `controllers/carbonaccountController.js`

- **Create** (`POST`): calculates the carbon fields and saves all four new values with the account.
- **Update** (`PUT`): recalculates the carbon fields from the new figures and saves them. The DynamoDB `UpdateExpression` now sets the four new attributes as well as the original three.
- **Get all / get by ID** (`GET`): run each record through `withCarbonFields()` before returning it, so accounts created before this update still come back with the new fields.
- **Delete**: unchanged.
- Fixed a leftover "Get the movie" comment.

### `README.md`

- Added this file.

### Not changed

- **`views/router.js`**: the routes are the same.
- **`carbonaccount_database.tf` and the DynamoDB table**: DynamoDB only needs the key (`id`) declared, so new attributes are stored as soon as the code writes them. A schema change would only be needed to query or sort by the new fields, which would mean adding a secondary index.

## Existing records

Accounts saved before this update don't have the new attributes in DynamoDB. They don't need migrating:

- `GET` requests return them with `baseline_emissions` and `net_carbon_reduction` of `0`, progress of `0%` and the base interest rate.
- The next `PUT` validates them with the same defaults and saves the new fields to the table.
